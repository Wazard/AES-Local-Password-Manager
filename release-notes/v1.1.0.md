Secure Vault 1.1.0 fixes a data-loss trap around moving the vault file, replaces
the OneDrive symlink with real dated backups you can restore from, and makes
account names editable.

## Fixed

- **A moved vault is no longer mistaken for a new one.** The vault path was
  hard-coded, and "nothing readable there" was treated as "first run" — so if
  you moved `vault.pwmanager`, the app showed a normal login screen and turned
  the next master password you typed into a brand-new, empty vault. Your
  accounts were never deleted, but the app had forgotten them. The vault's
  location is now recorded, it can live anywhere (another drive, a synced
  folder), and a vault that has gone missing gets a **Vault not found** screen
  offering to locate it again.
- **Creating a vault is now a deliberate choice.** Typing a master password into
  the login form can no longer create one.
- **A broken backup link no longer locks you out.** A dangling symlink used to
  read as "no vault" on one screen while importing refused with "a vault already
  exists here" on the other.

## Added

- **Dated backups.** A read-only encrypted copy is saved on every add, edit or
  delete, named `vault_bk_2026_08_08_1432_01.pwmanager` so the folder sorts
  chronologically. Kept in OneDrive when you have one. Retention keeps the
  newest 20 plus one per day for 60 days, so a busy afternoon can't push a
  month of history out.
- **Restore from inside the app.** The backup screen lists every copy with date
  and size. Restoring backs up the current vault first, so it is itself
  undoable.
- **Editable account names.** Renaming keeps the entry's position in the vault
  and refuses to overwrite another account.
- **Version on the login and settings screens**, so "did the update install?"
  has a visible answer.

## Changed

- **Backups replace the OneDrive symlink.** The old scheme moved the vault into
  OneDrive and left a link behind — it needed administrator rights or Developer
  Mode and kept only one always-current copy, so a mistake propagated instantly
  with nothing to roll back to. Existing links are retired automatically on
  first launch: the app records the file the link points at and drops the link.
  Your vault is never touched.
- **Search is faster.** Results, sort order and match text are cached until the
  vault changes, typing another character filters the previous result instead of
  rescanning, and the list is not redrawn when it hasn't changed. Over 400
  accounts, 200 repeated searches went from 25.5 ms to effectively nothing.

## Installing

Download **SecureVaultSetup.exe** below and run it. No administrator rights
needed — it installs per-user.

**Updating from 1.0.0:** run the installer over your existing copy; it upgrades
in place rather than adding a second installation. Close Secure Vault first
(including from the tray) — Setup will otherwise ask you to. If your 1.0.0 was
unzipped by hand rather than installed, Setup finds it and offers that folder as
the destination, so check the destination page.

Your vault, backups and settings live in `%APPDATA%\SecureVault` and are not
touched by updating — or by uninstalling.
